### 平台视频模型现状（`libtv model search -t video` 实测）

共 **35 个**视频模型。与工作流相关的四个：

| modelKey | modelName | 分辨率 | 时长 | image2video 参考图 | 备注 |
|---|---|---|---|---|---|
| `star-video2.5` | Seedance 2.5 | 480p/720p/1080p | **4–30s** | 1–30 | 唯一支持 `videoExtend2video` / `videoEdit2video`；定价规则：**按秒计价，上传的参考视频时长计入总时长** |
| `star-video2` | StarVideo 2.0 VIP | 480p/720p/1080p/**4k** | 4–15s | 1–9 | 之前跑通的那个 |
| `star-video2-fast` | 2.0 Fast VIP | 480p/720p | 4–15s | 1–9 | 无 1080p |
| `star-video2-mini` | 2.0 Mini | 480p/720p | 4–15s | 1–9 | 无 1080p |

2.5 另有：`supportLongVideo`、`supportVideoContinuation`、`audio2video [1,10]`、`count [1,2,4]`、`portrait`、`autoCompliance`；ratio 默认 `adaptive`（2.0 默认 `16:9`）。

**能力上真正的增量**：2.5 的 `videoExtend2video`（视频续写）+ 30s 上限 —— 这是目前唯一能缓解「镜头一致性按镜独立、镜头间融不起来」的机制，不是画质问题。

### 真人形象授权路径（来自 2026-04 第三方实测文章，入口措辞以网页实际为准）

- **AI 生成角色**：画布上传图 → 右键 →「Seedance 2.0 合规校验」→ 几秒出结果，图上出现标识即通过。
- **实拍真人**：视频节点「角色库」→ 添加真人角色 → **系统出二维码，本人手机扫码做人脸认证 + 确认授权协议** → 上传 3–5 张不同角度照片（正面 1 + 侧面 2 + 全身 1）→ 系统比对（须同一人、画面里不能有第二人）→ 1–2 分钟出角色模型 → 此后可复用。

授权必须本人到场（人脸认证），agent 做不了。

## 全量模型普查（同夜，34 视频 + 17 图片，只读）

报告：`libtv\LibTV模型选型全景-2026-09-22.html`；原始 schema 落在 `.tmp/schemas/`（51 份）。

### 硬筛结果：只有 10 个能挂 ≥3 张参考图

判定口径：`image2video` 上限 ≥3，或 `mixed2video` 上限 ≥3 **且** mixcfg 有独立 `imageMax` ≥3。
（`imageMaxWithVideo` 那种「必须带视频才挂图」的不算——kling-v3-omni / video-o1 / wanx2.7 / viduq2-pro / kling-v3-motion-control 都属此类。）

过筛 10 个：`star-video2.5`、`star-video2`、`star-video2-fast`、`star-video2-mini`、`wanx3.0`、`wanx3.0-prime`、`MiniMax-Hailuo-H3`、`happy-horse-1`、`happy-horse-1.1`、`viduq2`。

### 三条影响选型的硬事实

1. **只有 `star-video2.5` 和 `wanx3.0` 有 `videoExtend2video`（视频续写）** —— 这是目前唯一能接续镜头、缓解「一致性按镜独立」的机制。star-video2 全系都没有。
2. **`wanx3.0` 时长下限 2s、上限 30s**，是过筛名单里区间最宽的（star 系 4–15s，2.5 是 4–30s，H3 是 5–15s）。按秒计价时短镜头更省。
3. **`wanx3.0` 与 `H3` 都只能用 `mixed2video` 挂多图**（平台没给它们 `image2video`）→ 纯图能否成立**未验证**，这是首选候选的最大不确定性。

### 分辨率档位陷阱（比价时必看）

`720p`（star 系 / wanx3.0）与 `768P`（Hailuo 系）是不同像素体系，`2K` 与 `1080p` 亦然。schema 查不到像素值，只能拿成片 `ffprobe` 反推。

### 命名歧义（待实测）

`model search` 与 `model <key>` 的 modelName **不一致**：`star-video2` 在 search 里叫「Seedance 2.0 VIP」、在 schema 里叫「StarVideo 2.0」。另 `wanx3.0-prime`、`lib-image-2.5-s/f` 的 schema **没有 modelName 字段**（None）。→ 创建节点的 `-s model=` 到底写哪个，必须实测（建节点不带 `--run`，零积分）。

### 图片侧

17 个。`mj-*` 四个的 `count` 固定 `[4]`（一次必出 4 张，按张计价时是 4 倍，不适合当主力）。`lib-image-2.5-s/f` 与 `lib-image-2` 档位最细（1K/2K/4K + low→max 五档质量），最适合「草图低档、定版高档」分级省钱。

## 价格核实结果 → 定 wan3.0 为核心（财哥 2026-09-23 00:03 提供）

- **Seedance 2.5 与 wan3.0 差价 5 倍**。
- **wan3.0：720p / 10s / 带音频 = 80 积分** → 折合 **8 积分/秒**；2.5 同规格约 400 积分（40 积分/秒）。
- 决策：**以 wan3.0 为核心建立工作流**，2.5 退为「关键镜头备用 / 效果不达标时的升级路径」。

### 两条由计价方式推出的推论（不是价格数据本身，是它的后果）

1. **按秒计价 → 切成几镜不影响总价，只有「总时长 × 单位价」和「重复生成次数」影响钱。** 所以不必为省积分硬拼长镜头，该按叙事切就切；唯一真正的省钱动作是**不重复生成**（这也印证了早先「单镜只生成一次」的约定）。
2. **2.5 的核心增量已被 wan3.0 覆盖**：两者都有 `videoExtend2video`（续写）。2.5 剩下的独有优势只有「参考图 30 张 vs 10 张」与画质口碑 —— 5 倍差价下，只配用在刀刃上。

### 换核心的真实成本（必须记住）

**知识包写死的「槽位契约」作废**——那套「clean 九宫格→角色→场景→道具」四槽顺序是 `image2video` 模式的实测结论，而 wan3.0 没有 `image2video`、只能走 `mixed2video`。槽位语义、图数上限（10）、`{{Image N}}` 引用写法都要在 wan3.0 上重新验一遍，**不是零成本切换**。

### 关键对账（本次最有价值的发现）

官方规格 **图 10 / 视频 5 / 音频 5、duration 2–30s** 与 LibTV `wanx3.0` schema 的
`mixed2videoConfig {videoMax: 5, imageMax: 10, audioMax: 5}` + `duration (2, 30)` **完全一致**
→ **LibTV 是直接封装 Wan 3.0 的全模态参考能力，没有改规格** → **官方那套提示词公式可以直接搬用**。

**但要分清**：官方文档讲的是**阿里云百炼 API**，不是 LibTV CLI。参数名不同，且素材指代语法不同 ——

### 抓取方法（可复现）

阿里云帮助中心是 SPA：`curl` 带浏览器 UA 能拿到 HTML，但**正文被塞在页面 script 的 JSON 字符串里且已转义**。
解法见 `参考文档\raw\html2md.py`：反转义 → 剥 script/style 壳 → HTMLParser 转 md（**只在块级标签上 flush，行内标签不清 buf**，
否则 `<span>` 包裹的数字会丢）→ 从最后一个一级标题起算（正文在页面里出现两遍）→ 裁页脚。官方文档更新后重跑即可刷新。

### 最该记住的四条

1. **`-s model=` 只认 modelName**（CLI `node create --help` 原文：「传 modelKey 会报错提示」）。
   且 CLI 示例用的是中文名（`-s model=可灵O1`）→ wan3.0 写 `Wan 3.0`。
2. **默认值两边相反**：阿里云官方 wan3.0 分辨率默认 **1080P**，LibTV 侧默认 **720P**。LibTV 上不会默认烧钱，但换平台要留意。
3. **"不写"不等于"没有"**：wan3.0 有声默认开启，且**提示词不提台词/背景音乐时模型会自己加**（官方原文）。
   → 要做无声画面必须 `enableSound=off` **且**提示词显式写「无台词」「无背景音乐」。
4. **两条改变范式的官方能力**：多镜头公式（30s 一次生成 = 一个段落，不是一镜一节点）；
   视频延长（向前/向后/双向，接**真实尾帧**，输入+输出总时长 ≤30s）—— 后者是「镜头融不起来」的机制性解法，
   比知识包「段尾留光/门/手钩子」靠剪辑缝合强一个量级。
