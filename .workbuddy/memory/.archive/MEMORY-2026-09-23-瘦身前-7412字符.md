## ★ 命令语义（1.1.3）

1. ★ **prompt 指代用 `{{Node "节点名"}}`**（或 `{{Node <nodeKey>}}` 不带引号）；「图1」/ `{{Image 1}}` **作废**。只能引用**已连线**的上游，**同名多条 → 整条写入中止报错**；CLI **读回时显示为 `{{Node <nodeKey>}}`**，此层**不影响网页端展示**。⚠️ **后端还会再重写一次**（见「陷阱 1」）。
2. **`--run` 是同步等待命令**（提交 → 轮询 → 写回，stdout 出终态 JSON 才退出）—— 不要自己包轮询、不要加 timeout、看到 `[run] task=…` 别提前收工。
3. **`-s` vs `-u`**：`-s` 写 `data.params`（生成器参数，**走 schema 校验**）；`-u` 写 `data` 顶层（节点内容，**不校验**）。`-s ratio=16:9` 自动归位到 `params.settings`。
4. **连边**：`--left`=**确保**（无则建、不删已有）｜`--left-add`=增量追加｜`--left-rm`=移除；**`--left` 与 `-add/-rm` 互斥**。`--prompt` **覆盖** `-s prompt=`。
5. **`-u` 拒写** `params`/`label`/`type`/`action`/`taskInfo` 等（改名只用 `--name`）。

## 参数（wan3.0）

`modeType=mixed2video`（多图参考唯一入口）｜`ratio=9:16`｜`resolution=720P`｜`duration=2–30`｜`enableSound=off`｜`count=1`（别动）

- 输出像素：`720P`+`9:16` → **720×1280**。成片强制 9:16；源片非 9:16 用「放大到覆盖 → 居中裁切」，**不拉伸**。
- ★ **智能扩写 `extendPrompt` 别关**（官方 schema 原文「关闭后生成效果大概率会下降」）。
- ⚠️ **Wan 3.0 不支持 `multi_shot` / `multi_prompt`** → **多镜头只能写在同一条 prompt**。

### ★ 提示词规范

按官方 `wan3-pe` 五段式：【核心任务】（声明**每份素材的职责与范围**）→【情节概要】（编号节点 + 时间戳）→【音频风格】→【运镜与核心约束】→【负面提示词】。

- **图生视频：图已定死主体/场景/风格，正文只写「动态 + 运镜」，不复述画面里已有的东西。**
- 美学控制词表在 `阿里云官方-万相提示词指南.md`（光源/光线/景别/构图/焦段/机位/色调/运镜/风格/特效）—— **成串调用，别裸写散文**。
- **负面提示词必写**：`CG感，塑料质感，画面模糊，噪点，横向条纹伪影，结构错位…`。

## 素材通路

**素材进生成的唯一方式 = 画布节点 + 连线。** 账号级「资产」库**无任何 API**。

- `mixed2video` 纯图成立（图 ≤10，或图+视频 1–15）。**`imageList` 顺序 = 连线顺序**。
- 跨画布搬素材：`download -n "<节点名>" -p <旧画布uuid> -o <目录>` → `upload "<新名>" --resource <路径>`。⇒ **素材节点建一次、多镜复用**。
- ★ **NDJSON 管道嵌套**（官方推荐编排）：`(a && b && c) | d` 一条命令建整个 DAG —— stdout 逐行 JSON 自动连下游左侧；旁路节点用 `&&` 接在括号**外**；复用已有节点 `libtv node "名" | …`；终端节点加 `>/dev/null` 防污染上游。**别再一条条手工建 + 手工连线。**

## ★ 图片生成 + 分镜链路

**A. Slash 快捷**：`libtv image shortcut`，云端 **17 条**（配置 `188`）。⚠️ **任何静态文档里都没有，必须 `shortcut list` 现场拉**；**CLI 只报 16 条**（缺 `720_panoramic`）。**Slash 封装只 CLI 有**；MCP 有异步 `generation_submit(kind=image)` + 写库前校验（互补）；**模型目录 MCP 26 vs CLI 18** → 全量查 MCP，Slash 走 CLI。
- ★ **坑**：九宫格/25宫格/故事板产物是**一张拼图**，喂 `mixed2video` 按**一张图**算 → **先本地裁成单图**；CLI 侧 `-n` 必填且源节点须有参考图 ⇒ **两跳**。

**B. ★ `script` 节点 = 结构化分镜表**：数据在 `data.rows`，每行一镜，含 **`imageGenerationPrompt`**（画面）+ **`videoMotionPrompt`**（运动）。★ **`libtv script storyboard <节点>`** = 一键：建**分镜图组** → 按行数派生等量 `image` 子节点 → **逐张 run 并轮询**；**前置：该节点已 `--run` 出分镜行**。`-u rows='[...]'` 手改分镜表。**`script` 与 `storyboard` 共用数据结构**，只是视图不同。

## 已验证结论

- ✅ `-s model=` 只认 **modelName**，传 modelKey 报错。**`nebula-ultra` 的 modelName = `Lib Navo Pro`** —— 官方示例写的 `LibNano Pro` 是**错拼**（照抄必报错）。
- ✅ 多镜头公式**服从度极高**（产物 `测试-多镜头A组\`）。1 次 15s 与 3 次 5s **都是 120 积分**，差别只在返工粒度 ⇒ **最优 = 多镜头公式 + 视频延长**（段内保连贯，段间接真实尾帧）。
- ⚠️ **官方手册的模型样本采自 2026-04-14**（`node-types\README.md` 明写）→ 示例里的模型名容易过时。

## 云端剪辑边界

`video-clip` 节点：**只连线 = 简单首尾拼接**；写 `-u clipTimelineData` = **精细剪辑**（`clips[]` 带入点 `sourceOffset`、时长、**单 clip 音量 `decibel`**；轨级 `videoAudioVolume`/`audioTrackVolume`）。来源 id 由 CLI 按连线**自动维护**。
⇒ **云端能做裁剪/分割/出入点/音量**；**不能**转场/变速/字幕/超分 → 走本地 ffmpeg。

## 本地超分（不花积分）

- **ncnn-Vulkan（质量优先）**：`libtv\.tmp\ncnn\`，A770 正常。拆帧 → `realesrgan-x4plus` → cover 裁切 → 合帧（CRF 16 / slow）。
- **ffmpeg 传统法（快）**：本机 8.1.1。写实 CG 上 `scale=…:flags=lanczos,unsharp=5:5:0.7:5:5:0.0` 比 `libplacebo ewa_lanczos` 更锐无 halo。
- ★ **放大倍率越大，锐化越该收敛**（2.25× 下 0.70 出 halo，降到 0.35）。

## 陷阱

1. ★ **后端会重写你的 prompt**（issue #12 实证）：服务端把 message 改写后再发模型 —— 自动修拼写、**自动扩写**、**静默丢弃不认识的指令**（无报错）。`{{Image N}}` 是**后端层**。⇒ **提示词精调可能被覆盖或吞掉，无 API 可关**。
2. **「不写」≠「没有」**：wan3.0 有声默认开，提示词不提台词/配乐模型会自己加 → 无声画面必须 `enableSound=off` **且**提示词写「无台词」「无背景音乐」。
3. **真人参考图被硬拦**：机制 = `properties.portrait` + `autoCompliance.enable` → `--run` 前校验上游图，过则转 `asset://<assetId>`；未检出真人写 `portraitCompliantExempt`；**任一不过 → 整体中止**。`assetId` 由网页端人脸认证签发，CLI 绕不过。
4. 阿里云官方默认 **1080P**、LibTV 默认 **720P**，别搞反。
5. 给 `python` / `ffmpeg` 传路径必须 `C:\…`，不能 `/c/…`（`libtv` 在 Git Bash 下中文输出正常）。
6. **去水印实测未生效**（两版都带 `LibTV` 角标）→ 大概率取决于会员。`--vip` 的价值在**码率**（≈5.7×）→ 高码率版留给本地超分。
