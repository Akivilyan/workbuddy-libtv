## A. 内容审核与真人合规

【历史经验，未重测】视频模型提交后可能经过内容安全审核。审核失败的积分或退款处理不可预设；在提交任何探针前仍应取得用户对付费视频生成的确认。

### A.1 两种失败信号——先分清，解法完全不同

提交后看节点的 `failedReason` / 画布红字，是哪一种决定你走哪条路：

| 失败信号（报错文案） | 含义 | 解法方向 |
|---|---|---|
| `输入内容未通过安全审核` | **普通内容审核**：画面/prompt 里有被判敏感的元素（暴力、血腥、政治、色情擦边，或**被误判**的构图） | 走 **A.2 二分排查法** 定位真凶元素，改构图/换措辞 |
| `参考图可能包含真人形象，请先合规校验` | **真人形象门槛**：某张参考图里有被识别为真实人脸的内容 | 走 **A.3 真人形象墙** 处理（合规校验 / 纯文字描述） |

⚠️ 【历史经验，未重测】两者别混。真人门槛不是靠改 prompt 能绕的（它判的是参考图像素），普通审核也不是靠真人合规校验能解的。先读准文案再动手；任何退款以平台可见确认结果为准。

### A.2 5s 试探片 + 参考图二分排查法（定位普通审核真凶）

【历史经验，未重测】审核失败时不要拿原配置反复重抽。经用户确认后，用极简短时探针定位到底是哪个元素触发的：

**核心思路**：用最短时长 + 最白话的 prompt + 逐个增减参考图，把变量降到最少，约 1 分钟出一次审核结果。

```
步骤：
1. 起一个探针节点：使用当前 schema 允许的短时长（审计时为 4–15 秒）、较低可用分辨率，
   prompt 改成极简白话（"两个人在客厅，温馨"——去掉所有可能敏感的形容词/动作词）。
2. 先全空参考跑一次：过 → 说明真凶在参考图；不过 → 真凶在 prompt 文字。
3. 若在参考图：二分法逐个摘参考图（先摘一半，过了就在被摘的那半里继续二分）。
   ~1 分钟一轮，几轮锁定到具体那一张/那个格子。
4. 若在 prompt：逐句删形容词/动作，定位敏感词。
5. 锁定后改构图或措辞，再用正式配置出片。
```

**为什么用短时探针**：【历史经验，未重测】它可缩短排查反馈；审核时点、结果一致性和任何退款都须以当前平台实际结果为准。探针只为排查，不看画质。

> **案例（历史经验，未重测）**：某高潮镜头三连拒（都报“输入内容未通过安全审核”）。二分排查锁定真凶 = 九宫格里一格“**人脸贴狗大特写**”被误判（疑似擦边）。把该格从“人脸贴狗”改成“**摸狗头中景**”即一次过。
>
> **通用教训**：人/宠物**贴脸大特写**慎用，容易被误判；同理高度贴近的双人脸特写、亲密肢体特写也是高风险构图。能用中景表达就别上大特写。

### A.3 真人形象墙（最硬的一道墙）

视频模型**拒绝任何含真实人脸的参考图**。这道墙比普通审核硬得多：

- **CG 化拦不住**：把真人照片做成插画/卡通风，仍可能被识别为真人形象。
- **裁剪也拦不住**：实测裁到只剩腿、只剩狗、只剩背景的局部，依然可能被判"包含真人形象"。识别很激进。
- 一旦命中，报 `参考图可能包含真人形象，请先合规校验`，整个任务 fail。

**正路（唯一可靠）= 平台官方真人形象授权校验**
- 在**网页端**走平台的真人形象合规/授权校验流程（上传本人证件 + 人脸比对，确认你有权使用该真人形象），校验通过后该形象才允许进生成管线。
- 这是平台合规要求，CLI 绕不过，必须人去网页端做一次。

**备选（绕过，但有代价）= 纯文字描述长相，不挂真人图**
- 完全不传真人参考图，改用**文字把这个人的长相特征描述清楚**，让模型凭文字生成。
- 代价：**相似度只有六七成**——能抓住大致气质/发型/脸型，但不会是"这个人本人"。
- 适用：对"像不像本人"要求不高、或本来就是风格化呈现的镜头。

#### 把真人特征提取成文字描述的方法

目标是把一张真人照片，转成模型能复现的**结构化长相 prompt**。按以下维度逐项写，越具体越稳：

| 维度 | 要写清的点 | 示例措辞 |
|---|---|---|
| 年龄气质 | 年龄段、整体气质 | "50岁、温和知性" |
| 脸型 | 圆/方/瓜子/长脸、脸颊饱满度 | "圆脸颊、下颌柔和" |
| 发型 | 长度、卷直、分缝、刘海、颜色 | "深红棕、及肩波浪卷、侧分、无刘海" |
| 五官 | 眼型、鼻、唇、特征点（痣/酒窝/法令） | "细长眼、温和浅笑、薄唇" |
| 肤色 | 冷暖、深浅 | "暖白皮" |
| 标志性穿着 | 如果某人总穿某类衣服，写进去强化辨识 | "黑立领盘扣旗袍式上衣" |
| 身材/比例 | 身高感、头身比（成年约 6.5 头身） | "中等身高、成年6.5头身" |

写法要点：
- **正面穷举**，按"年龄→脸型→发型→五官→肤色→穿着"顺序写成一段，别用否定句堆细节。
- 多镜复用同一人时，把这段描述**固化成可复制模板**，每镜原样粘，保证跨镜一致（文字描述天然比挂图易漂移，靠原样复用兜住）。
- 若该角色有"换装镜头"，描述里把脸型发型那几句保留、服装那句替换，并正面写新服装款式（见环境块外的"服装渗透"通用经验）。

> **案例**：按真人照片定的后妈 / 闺蜜角色，因走视频管线无法直接挂真人照片，最终用上述结构化文字描述固化成模板，逐镜复用，相似度约六七成、跨镜一致可接受。

## B. Windows / PowerShell / 中文环境怪癖

在中文 Windows + PowerShell 下驱动 libtv CLI，有一批反复踩的环境坑。下面每条都给**根因 + 解法**。

### B.1 `.ps1` 文件中文被 GBK 读成乱码 → 不写 .ps1，用内联

**根因**：PowerShell 读 `.ps1` 脚本文件时按系统区域编码（中文系统 = GBK）解码，UTF-8 写的中文 prompt 会变乱码，传给 CLI 就是垃圾字符。

**解法**：
- **中文 prompt 一律内联执行**，不落 `.ps1` 文件——直接用 Bash 工具或 PowerShell 工具把命令（含中文 prompt）整条传进去执行，让中文只存在于进程参数里，不经过 .ps1 的磁盘解码环节。
- **确实需要落脚本时写 `.py`**：Python 源码按 UTF-8 读取安全，中文不乱码。把批量逻辑（轮询、下载、拼接）写成 `.py`，PowerShell 只负责调 `python xxx.py`。

```python
# 落脚本就用 .py（UTF-8 安全），不要用 .ps1 存中文
# -*- coding: utf-8 -*-
PROMPT = "两个人在温馨客厅，2D绘本插画风格…"   # 中文不会乱码
```

### B.2 前台 `Start-Sleep` 被 harness 拦截 → 用后台任务或 until 循环

**根因**：Agent harness 拦截前台阻塞式 sleep（`Start-Sleep` 直接在前台调用会被挡）。

**解法**：
- 长耗时任务（视频生成 4-8 分钟/镜）用 **`run_in_background`** 提交，完成后被通知，不在前台干等。
- 需要轮询等待某条件时，用 **Bash until 循环**做条件等待，而不是前台 sleep；或把"提交 + 轮询 + 下载"整体丢进 `run_in_background`。
- 别用 sleep 循环硬重试失败命令——先定位根因。

```bash
# Bash until 循环等待（条件满足才退出），代替前台 Start-Sleep
until <检查命令返回成功>; do sleep 30; done
```

### B.3 对话框附件 Claude 读不到磁盘字节 → 让用户存进项目目录给路径

**根因**：用户在对话框里贴的附件（图片等）Agent 拿不到磁盘上的真实文件字节，而 `libtv upload -f <path>` 需要一个**本地真实路径**。

**解法**：让用户把文件**另存到项目目录**，把**绝对路径**告诉你，再用该路径 `libtv upload`。没有本地路径就 upload 不了。

### B.4 OpenCV `cv2.imread` 读不了中文路径 → 用 imdecode/imencode

**根因**：`cv2.imread` / `cv2.imwrite` 底层不处理中文（非 ASCII）路径，中文目录下直接返回 `None` / 写失败。

**解法**：用 NumPy 中转读写——`np.fromfile` 读字节再 `cv2.imdecode`，`cv2.imencode` 编码后 `tofile` 写。

```python
import cv2, numpy as np

def imread_cn(path):   # 读中文路径
    return cv2.imdecode(np.fromfile(path, dtype=np.uint8), cv2.IMREAD_COLOR)

def imwrite_cn(path, img, ext=".png"):   # 写中文路径
    ok, buf = cv2.imencode(ext, img)
    if ok:
        buf.tofile(path)
    return ok
```

### B.5 竖拍手机照片方向不对 → 上传前按 EXIF 转正

**根因**：手机竖拍照片像素本身是横的，靠 EXIF Orientation 标记显示为竖；很多处理/上传链路不读 EXIF，结果图被当横图处理，人物躺倒。

**解法**：上传前用 PIL 按 EXIF 转正（`ImageOps.exif_transpose`），落成"像素本身就是正"的图再 upload。

```python
from PIL import Image, ImageOps

img = Image.open(src_path)
img = ImageOps.exif_transpose(img)   # 按 EXIF 把方向转正、再清掉 EXIF
img.save(dst_path)                    # 上传这个转正后的文件
```

### B.6 PowerShell 中文输出乱码 → 设 `PYTHONIOENCODING`

**根因**：PowerShell 控制台默认编码非 UTF-8，调 Python 等子工具时中文 stdout 可能乱码。

**解法**：调用其他 Python 工具前设环境变量（libtv CLI 内部多数已处理，但你自己起的 Python 仍需要）。

```powershell
$env:PYTHONIOENCODING = "utf-8"
```
