# LibTV 端到端制作方法论：从 0 到成片

> 跨项目通用的 **AI 动画/写实短片生产流程**（基于 LibTV CLI + `star-video2` / StarVideo 2.0 视频模型 + nebula-ultra 图片模型）。
> 本文把"怎么从一句话做到一支成片"抽象成方法论；具体技术命令见同目录 `cli-reference.md`（命令矩阵 / modeType / `-s` vs `-u` / NDJSON）。
> 文中带"（案例）"的是某 30 镜生日短片项目的真实经验，仅作举例，**方法论本身不依赖任何具体项目**。

> **2026-08 v2 边界**：当前 CLI/schema 与受控多参考 `image2video` 的唯一顺序以 [AGENTS.md 槽位契约](../AGENTS.md#32-参考图槽位契约唯一准则)和[能力快照](capability-snapshot-2026-08-05.md)为准。除明确标注【2026-08-05 实测】/【实时 schema】外，本文的模型行为与生产启发式均为【历史经验，未重测】。

## 0. 心智模型：为什么是这套管线

AI 视频模型（StarVideo / Seedance 类）的根本特性决定了流程：

- **模型擅长"动起来"，不擅长"从零想清楚怎么拍"**。所以必须由人/故事板先把"构图·景别·运镜·表演"定死，模型只负责把静态意图变成连贯运动。
- **模型对参考图忠实、对文字描述健忘**。凡是要保持一致的东西（角色长相、场景布局、道具造型），都得用**定版图**当锚点喂进去，不能靠文字复述。
- **模型一致性按镜独立**。每个镜头是独立生成，镜头之间天然"融不起来"——靠**剪辑层的转场+配乐+旁白**缝合，不靠单镜自己收尾。
- **模型会"照抄参考图里的一切"**，包括你不想要的（格号数字、箭头、文字、彩色、多余实体）。所以喂给模型的图必须先**清洗**。

由此得到核心管线（五个阶段，每阶段产物喂下一阶段）：

```
①前期定调 → ②九宫格故事板(黑白线稿) → ③clean喂片版(去标注/去彩色)
   → ④单镜 image2video(挂 clean九宫格+角色/场景/道具定版图) → ⑤ffmpeg 统一终剪
```

风格分工铁律（贯穿全程）：
> **九宫格只负责"怎么拍 / 表达什么"（构图·景别·运镜·表演）；风格与色彩由"定版设定图 + 质感词"承担。** 两者各管一摊，不要让九宫格带颜色，也不要让质感词去描述构图。

## 阶段一 · 前期：定调 + 建定版资产 + 画故事板

这是整片质量的天花板，**前期偷懒后期翻倍返工**。三件事：

### 1.1 定美术基调 + 锁死"质感词"

- **二选一并固定**：2D 绘本动画插画 **或** 写实/CG。一旦定下，全片所有镜头共用同一套"质感词"，绝不中途混用（混用→风格撕裂，案例中早期 3D/C4D 路线整体作废重来）。
- **质感词 = 一段可复制的固定字符串**，正面描述目标质感 + 负面排除对立质感。每镜 prompt 直接粘贴。

  2D 绘本基调示例（案例）：
  ```
  2D柔和动画绘本插画风格，柔和干净线条，温暖平涂上色，绘本质感，温暖自然光，
  gentle 2D storybook animation；绝不要3D渲染/C4D/Octane/写实立体/照片真实感
  ```
  写实基调可对调正负面（强调"照片级真实/自然光影/实拍质感"，排除"卡通/插画/3D塑料感"）。

- **质感词只管风格，不管内容**。每镜的"画面里有什么、怎么动"另写。

### 1.2 建角色 / 场景 / 道具"定版设定图"并上传 LibTV 作锚点

**定版图 = 全片唯一权威外观来源。** 凡画面涉及已定版的元素，生成时**必须挂对应定版图作参考锚点**，绝不允许只靠文字描述还原。当前受控多参考 `image2video` 的图位使用下述槽位契约；不要写成“角色总在第一张”。

| 资产类型 | 定版要求 | 喂图时的位置 |
|---|---|---|
| 角色 | 一张干净的角色定版图，确定脸型/发型/服装/头身比 | 当前受控多参考中为第 2 槽，唯一外观依据 |
| 场景 | 场景定版图，确定家具布局/空间结构 | 当前受控多参考中为第 3 槽，只确定布局 |
| 道具 | 关键道具定版图；造型特殊的道具尤其要定版 | 第 4 槽起按需加入；见 §4.3 in-scene 锚定法 |
| 同类多实体 | 用"干净版"参考（每个实体一张，不要姿态拼图） | 配强数量约束（案例：狗只能 2 只，用 `dogs_clean` 双狗干净图，禁姿态拼图——拼图会诱发多实体） |

定版治理要点：

- **定版后归档不动**（案例：`产出/定版归档/`）。需要改某个定版，用**新节点名/新文件名**（如 `xxx_v4`）引用旧版重做，成功后再清理旧版——**绝不先 delete 再 create 同名并自引用**，否则引用落空、模型凭文字重画（案例 18 后妈丢失）。
- **涉及真实人物/真实仪式/真实道具的镜头，先向用户拿真实参照（照片/口述）再设计**，不要凭脚本文字推测（案例 28 领证构图 / 30 蛋糕造型，凭空推测全错）。
- **比例/身高等跨镜恒定属性，做一张"对比参照图"当锚**（案例 `r_height_ref`：女主 1.7m / 闺蜜 1.5m，同框高差固定）。

### 1.3 画"黑白素描九宫格故事板"

- **一镜一张九宫格（9 格）**，每格 = **一个运镜/表演节拍**（推近、转头、抬手、对视…），9 格按时间推进、各有动作，**不要 9 格来回重复同一动作**（重复→视频内容单调）。
- **必须黑白铅笔素描线稿，不上色**。颜色是设定图+质感词的事。九宫格带颜色会污染出片（案例 17/18：挂彩色场景图导致素描格首末格混入彩色）。
- **段尾留"转场钩子"**：每个叙事段的最后一镜，结尾画一个可供下一镜承接的"出口"——光、门、手是最通用的三个母题（案例：望窗晨光→下一镜光里出现 / 推门 / 递手）。钩子让剪辑期的转场有的可接。
- **格内零文字零数字**：单据画横线示意、屏幕画亮屏不写字、消息画气泡不写内容。九宫格里画了文字，视频会照抄进画面穿帮（案例 20 账单文字 / 27 气球上的格号"②"）。

## 阶段二 · 九宫格处理：重绘对齐 + clean 喂片版

用户工具/AI 初画的九宫格往往与定版不一致（角色漂移、幼态化、比例错、混了彩色）。处理分两步：

### 2.1 不一致时用 nebula-ultra **重绘**（不是局部编辑）

> 关键判断：角色长相/比例/风格跑偏 → **重绘**；只改一个局部细节（一行字、一个道具）→ image2image 局部编辑。

**重绘配方**（案例验证）：

| 要素 | 设定 | 原因 |
|---|---|---|
| 模型 | nebula-ultra（编辑/一致性强） | |
| 分辨率 | **4K** | 2K 时小格的脸会糊、变形（案例 13-16） |
| 角色外观锚点 | **角色定版图** | 【历史经验，未重测】只取脸型发型服装，锁定角色外观 |
| 构图锚点 | 原九宫格 | 【历史经验，未重测】只取构图/景别/运镜，不取它的角色画法 |
| 【角色铁律】 | “严格按角色定版图，9 格同脸、同发型、同服装” | 防格间漂移 |

> 【历史经验，未重测】上表用于 image-to-image 故事板重绘；它不是本次 A/B 所测试的多参考 `image2video` 槽位规则。
| 【人物比例铁律】 | 写明年龄 + 成年约 6.5 头身 + 禁幼态/大头娃娃/裁切头部/五官变形 | 防幼态化、防裁头 |
| 【纯黑白铁律】 | "全部 9 格（特别是第 1/9 格）纯黑白，彩色参考只取结构转线稿" | 防彩色渗透 |

发型等细节选"成年感"的版本（案例：用高马尾，别用丸子头，避免幼态联想）。

### 2.2 出片前做 **clean 喂片版**

九宫格上的**格号数字、箭头、任何标注、残留彩色**都会被视频忠实照抄。出片前对最终九宫格做一次清洗：

- nebula-ultra image2image：prompt = "**去掉所有格号数字/箭头/标注，其他完全不变**"，产出 `sb_XX_clean`。
- 重要镜头（高潮戏/复杂构图）**一律用 clean 版喂片**。
- **clean 版也要逐格 QC**：clean=重绘，重绘过程可能"幻觉加戏"（案例 29B：clean 时某格凭空多画了一只狗，视频忠实照抄出穿帮）。穿帮反复出现连改不掉时，**先查所有参考图里有没有那个元素，再怪 prompt**。

## 阶段三 · 单镜生成 SOP（标准作业流程）

每个镜头独立走这套流程。**核心纪律：先报方案求用户确认，再 `--run`。**

### 3.1 固定出片参数（全片统一）

| 参数 | 试错值 | 定稿值 | 说明 |
|---|---|---|---|
| `model` | `StarVideo 2.0` | `StarVideo 2.0` | 【实时 schema】创建参数为 modelName；查询键为 `star-video2` |
| `modeType` | `image2video` | `image2video` | 多图参考，首图作首帧候选 |
| `ratio` | `16:9` | `16:9` | 全片统一画幅 |
| `resolution` | **`720p`** | **`1080p`** | 720p 试错省积分，定稿才上 1080p |
| `duration` | 8 | 按片定 | 【实时 schema】允许 4–15 秒；缩短长镜头是【历史经验，未重测】 |
| `enableSound` | `off` | 按片定 | 【实时 schema】允许 `on`/`off` |

> 【历史经验，未重测】先用 720p 跑通方案、再用 1080p 定稿是生产选择；不可承诺固定积分价或退款。

### 3.2 挂图清单（每镜按九宫格实际画面决定）

> 挂哪些参考，由**该镜九宫格的实际画面内容**决定，不按旧剧本文字加戏。

```
①clean 九宫格(拍摄脚本) → ②出现的角色定版图 → ③场景定版图 → ④道具/同类实体定版图
```

- prompt 用 `{{Image 1}}`/`{{Image 2}}`… 按连线顺序引用第 N 个上游。
- 标注九宫格的角色：prompt 写"`{{Image 1}}` 九宫格是**唯一拍摄脚本**"。

### 3.3 prompt 结构模板（正面穷举 + 铁律 + 质感词）

```
【拍摄脚本】{{Image 1}} 九宫格是唯一分镜脚本，严格按 9 格顺序运镜表演。
【角色锚定】{{Image 2}} 是<角色>定版，严格按此脸型发型；<服装如何处理见下>。
【场景锚定】{{Image 3}} 是场景定版，家具布局严格按此保持不变。
【画面元素铁律】画面里有且只有：<正面穷举所有该出现的元素>。
【绝对零文字零数字】画面不出现任何文字、数字、格号、箭头、字幕、水印。
【镜头铁律】镜头始终以人为主体紧跟不离开，禁止长段空镜/环境展示运镜，场景只是背景。
【质感词】<粘贴 §1.1 固定质感词>
```

关键 prompt 技巧（案例提炼）：

| 目标 | 写法 |
|---|---|
| **排除某元素**（防"别想大象"效应） | Seedance 负面指令弱：**通篇不提该元素的名字**，改用【画面元素铁律】**正面穷举**"画面里有且只有…"。负面词"禁止出现狗"反而召唤出狗（案例 29B 连 3 版） |
| **换装**（角色设定图服装渗透） | "第 X 张图只用来确定脸型发型，**衣服完全不按图**" + 正面描述新服装 + 负面排除原款式特征（案例 08：便装日仍穿校服） |
| **特殊着装/场景** | 写【装备铁律】正面穷举（案例 29B 水下：全程面镜+呼吸管+脚蹼+漂浮姿态非站立） |
| **道具锚定** | **in-scene 锚定法**：用"道具已摆进场景"的合成图（案例 `cake_in_living`）替代独立道具图，prompt 写"和图中桌上的 X 一模一样"——照抄在场比凭图重摆可靠（案例 30 蛋糕） |
| **长镜头防场景漂移** | 【场景锁定铁律】"全程同一房间、家具布局严格按场景图、禁止切换房间/家具消失"（案例 02：9s 后客厅变样板房） |
| **防"贫穷/破败"滤镜** | 删掉所有联想贫穷的词（农村/砖房/90 年代），只正面描述"被好好打理的温馨家"+ 硬负面"禁止墙皮脱落裸砖污渍裂缝"（案例 05） |
| **男性配角/敏感同框** | 虚焦/背影/不画清晰脸，且**绝不与主角肢体接触** |

### 3.4 报方案 → 确认 → 后台提交

**铁律：生成视频前必须先把方案（挂哪些图、prompt 要点、时长）告诉用户，得到"可以/OK"才 `--run`。绝不擅自触发视频。**（图片生成——用户明确要的道具/首帧——可直接做，不需逐次确认。）

确认后用**后台任务 + 轮询**模式提交（详见阶段四）。

## 阶段四 · 自查：后台轮询 + create-then-verify + 抽帧 QC

【2026-08-05 实测】两次 `node create --run` 前台调用超时，但后端继续。超时并不证明作业失败：先查询**既有同名节点**，确认是否存在及其状态，再决定是否重试；只有确认不存在时才创建新节点。

### 4.1 后台任务 + 轮询循环

用 `run_in_background` 提交 `node create --run`，然后另起一个轮询循环：

```powershell
$libtv = "$env:USERPROFILE\.libtv\libtv.exe"
$node = & $libtv node "镜头XX" | Out-String
if ($node -match '"count":\s*0' -or $node -match '"matches":\s*\[\s*\]') {
  throw "VERIFIED_ABSENT：记录节点不存在并停止；重新报告方案与当前毛预算、再次取得用户明确批准后，才可手动提交一次 create"
}
# 节点存在：继续查询其状态。只在结果经检查为 MP4 后再下载；
# 不把输入资源地址当结果，也不在文档中记录远端结果地址。
```

要点：
- 【2026-08-05 实测】只消费验证为 MP4 的结果；不要把输入资源当作输出，也不要在文档或证据中保留远端结果地址。
- 【历史经验，未重测】如遇明确的后端失败，先分类原因；审核/真人形象属于内容或合规问题，不能靠原样重复提交解决。
- 超时 `--run` 报失败后先查既有节点，再决定是否重试。

### 4.2 create-then-verify（防静默失败）

【历史经验，未重测】`node create` 曾出现不报错但未建成的情况。create 后立即查节点；确认节点不存在只说明首次提交没有留下节点，**不构成再次生成的授权**：

```powershell
& $libtv node create "镜头XX" ... --run
$check = & $libtv node "镜头XX" | Out-String
if ($check -match '"count":\s*0' -or $check -match '"matches":\s*\[\s*\]') {
  # 1) 记录 VERIFIED_ABSENT；2) 立即停止执行。这里不得 create、不得进入自动循环。
  throw "VERIFIED_ABSENT：等待重新报告与再次批准"
}
```

节点被确认不存在后，恢复流程必须按顺序执行：

1. 记录节点名与 `VERIFIED_ABSENT` 结果。
2. 停止执行；不得自动重试、自动重建、删除后重建或进入 retry/create 循环。
3. 向用户重新报告本次要挂的输入图及顺序、prompt 要点、模型与全部生成参数、时长/分辨率，以及**包含本次拟重提在内的当前毛预算**。
4. 等用户再次明确回复“可以/OK”；旧批准不自动延续到重提。
5. 只有收到新批准后，才在一次新的手动步骤中提交**一次** `node create --run`，随后回到“查询既有同名节点”的流程。若仍不存在，再次停止并从第 1 步开始，绝不自动循环。

### 4.3 抽帧自查（Read 对照图，过了才报用户）

**每条视频生成后，先自查再报用户。** 用 ffmpeg 抽 4–10 帧拼成一张对照图，用 Read 工具看图逐条核对 checklist：

```powershell
# 抽 6 帧均匀采样并横向拼接成一张对照图（DUR=该片时长秒数，fps=6/DUR 即全片均匀取 6 帧）
ffmpeg -i 镜头XX_v1.mp4 -vf "fps=6/<DUR>,scale=320:-1,tile=6x1" -frames:v 1 镜头XX_qc.png
# 简化版：不必算时长，按固定帧间隔抽帧（每 30 帧取 1 帧，拼 5x2=10 格）
ffmpeg -i 镜头XX_v1.mp4 -vf "select='not(mod(n\,30))',scale=320:-1,tile=5x2" -frames:v 1 镜头XX_qc.png
```

自查 checklist（逐条过）：

- [ ] **角色一致**：脸型/发型/服装与定版图一致，9 格没漂移
- [ ] **人物比例**：头身比对、无幼态化、无裁头、五官不变形
- [ ] **无穿帮文字**：画面无格号/数字/箭头/字幕/单据文字
- [ ] **同类实体数量**：数量严格正确（案例：狗只能 2 只，无第三只/分身）
- [ ] **服装正确**：换装镜头穿对衣服，没渗透设定图原款式
- [ ] **场景锁定**：长镜头全程同一房间，家具没漂移/消失
- [ ] **运镜符合九宫格**：以人为主体，没变成空镜/环境展示片
- [ ] **转场钩子**：段尾镜头结尾留了光/门/手出口

**穿帮排查顺序**：穿帮反复出现连改不掉时，**先逐张检查所有参考图（含 clean 版）里有没有那个元素，再怀疑 prompt**——真凶常在参考图（案例 29B：clean 格里被画进的狗）。

### 4.4 真人照片合规墙（硬限制，必须知道）

Seedance 视频模型对"**含真人形象的参考图**"会拒，报"参考图可能包含真人形象，请先合规校验"——**连 CG 化/裁剪都拦不住**。应对：

- 必须走**平台官方真人形象授权校验**（网页端走授权流程）。
- 或**纯文字描述长相、不挂真人图**可绕过审核，但相似度打折。
- 【历史经验，未重测】另一类审核拒（“输入内容未通过安全审核”）可用短时探针 + 参考图二分排查定位可疑构图；退款/积分必须以平台可见确认结果为准。人+宠物贴脸大特写慎用。

### 4.5 用户反馈 → 逐镜返工

自查过了才报用户。用户反馈后**逐镜返工**：定位是九宫格问题（回阶段二重绘/clean）、prompt 问题（改 §3.3 写法）、还是参考图问题（换定版图）。

---

## 阶段五 · 批次节奏：小批确认 + 整批预览

不要一口气跑完所有镜头再给用户看。**分批推进**：

1. **每批 3–5 镜**。
2. **逐镜确认**：批内每镜走完阶段三 SOP（报方案→确认→生成→自查）。
3. **整批拼带转场预览**：本批镜头齐了，用 ffmpeg 拼一段"带转场的预览"给用户看**整体感觉**（不是看单镜），确认风格连贯、转场顺、节奏对。
4. 整批 OK 再开下一批。

这样能在早期（前 1–2 批）暴露系统性问题（风格不对、角色不像、转场逻辑不顺），避免后期全片返工。

---

## 阶段六 · 终剪：ffmpeg 缝合 → 1080p 定稿

全部镜头（1080p 定稿版）齐了，进入统一剪辑。

### 6.1 终剪要素

| 要素 | 做法 |
|---|---|
| **转场链** | 按预先设计的转场方案（案例：光/门/手三母题，29 个转场点），用 ffmpeg `xfade` 串联；段尾钩子与下一镜入口对接 |
| **配乐** | 连续 BGM 跨整片；若用 LibTV 音乐模型生成，**必须加 `-s scene=Music`**（音频节点默认 TTS 场景，不加会报"场景不一致"） |
| **音轨处理** | 【历史经验，未重测】若片源实际带有音轨，可在剪辑时用 `acrossfade` 随 `xfade` 同步交叉；不要假定 `enableSound=off` 仍会产出环境音轨 |
| **旁白**（可选） | 第一人称旁白 + 字幕，按剧本逐段对齐 |
| **片尾字幕卡 + 封面** | 片尾字幕卡、封面帧 |
| **定稿分辨率** | 1080p |

### 6.2 拼装核验（防笔误）

手写镜头序列**极易笔误**（漏一镜/重复一镜，案例：漏 15、重复 16）。拼装后必须：

- **核对 clips 数 = 镜头数**；
- **核对序号连续**（01→30 无跳号无重复）；
- **核对成片总时长 = 各镜时长之和的预估**，对不上要回查哪镜漏了/重了。

### 6.3 中文/路径踩坑（终剪期高发）

| 坑 | 解法 |
|---|---|
| `.ps1` 文件中文被 GBK 读乱码 | 中文 prompt/参数用**内联** PowerShell，不写进 .ps1 文件 |
| `cv2.imread` 读不了中文路径 | 用 `cv2.imdecode(np.fromfile(p,dtype=np.uint8),1)` 读、`imencode`+`tofile` 写 |
| PowerShell 调外部 Python 工具中文乱码 | `$env:PYTHONIOENCODING = "utf-8"` |
| 对话框附件读不到磁盘字节 | 让用户先存到项目目录给路径，LibTV 才能 upload |

## 附录 B · 一句话 SOP 清单（贴在工作台前）

1. 定基调 → 锁一段固定质感词（一片一基调）。
2. 建角色/场景/道具**定版图**并上传；当前多参考 `image2video` 按槽位契约使用 clean 故事板→角色→场景→道具。
3. 画**黑白素描九宫格**：每格一个节拍，段尾留光/门/手钩子，格内零文字。【历史经验，未重测】
4. 不一致 → nebula-ultra **4K 重绘**（【历史经验，未重测】角色定版图作外观锚点 + 原九宫格作构图）。
5. 出片前做 **clean 喂片版**（去格号/箭头/彩色），逐格 QC。
6. 单镜 `image2video`：按槽位契约挂 clean九宫格+角色+场景+道具，先用 `star-video2` 查询 schema，再以 `StarVideo 2.0` 创建；720p/8 秒是生产选择。
7. **先报方案求"OK"，再 `--run`**。后台提交后查询既有节点；确认不存在前不重建。
8. 抽帧拼图 **Read 自查**逐条 checklist，过了才报用户。
9. **每批 3–5 镜**逐镜确认，整批拼带转场预览看整体，再下一批。
10. 全齐 → ffmpeg 转场链+配乐+旁白+片尾+封面 → **1080p 定稿**，拼后核对镜数/序号/时长。
