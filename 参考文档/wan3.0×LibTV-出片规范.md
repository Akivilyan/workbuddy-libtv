## 0. 为什么这份文档存在

知识包（`libtv-video-agent`）是围绕 **Seedance / StarVideo 2.0** 写的，它写死了一条 `image2video` 的槽位契约。
我们改用 **wan3.0** 之后，那条契约作废；而 wan3.0 恰好有一份**比知识包权威得多的一手官方文档**——
阿里官方给出了它自己的四套提示词公式。**本文件就是把那套官方语法落到 LibTV 的 CLI 上。**

## 1. 官方规格速查（wan3.0-video / wan3.0-video-prime）

> ★ **来源与权威顺序**：LibTV 的 `wan3.0` = 阿里 `wan3.0-video` 的**接入版**（阿里官方原文「**Flova、Libtv、美图等也已完成接入**」）→ **模型能力 / 参数 / 计价的争议，一律以原厂为准**：`help.aliyun.com/zh/model-studio/wan3-0-video`。
> LibTV 的增量只在**画布编排层**：生成能力与阿里 API **等价**（全模态参考 20 素材、首帧/首尾帧、视频编辑、视频延长、`图1` ↔ `{{Image N}}` 同构）；多出来的是画布 / 节点 / 连线 / Slash 封装 / 运镜预设 / 多模型聚合。

**能力总述**：All-in-One 视频模型；单次最长 **30 秒**、**30fps**；**原生输出台词、BGM、音效**；单次最多 **20 个多模态素材**参考；支持首帧/首尾帧控制、视频编辑、视频延长。

### 任务类型与触发方式

| 任务类型 | 触发方式 | 说明 |
|---|---|---|
| 文生视频 | 仅传 prompt，不传素材 | 可自由设分辨率/比例/时长 |
| 图生视频·首帧 | `type=first_frame` | `ratio` 建议 `adaptive` |
| 图生视频·首尾帧 | `type=first_frame` + `last_frame` | `ratio` 建议 `adaptive` |
| **全模态参考** | `type=reference_image` / `reference_video` / `reference_audio` 任意组合 | 我们主用这条 |
| 文件/网页生视频 | `type=file` 或 `link`（二选一） | 解析文档/公开网页内容 |
| 视频编辑 | `reference_video` + 提示词含编辑意图（"编辑/去掉/替换/改成"） | `duration` 建议 -1 |
| 视频延长 | `reference_video` + 提示词含延长意图（"延长/延续/向前/向后"） | `duration` 建议 -1 |

### 素材上限

| 素材类型 | 上限 |
|---|---|
| 参考图 `reference_image` | **≤10 张**，单张 ≤20MB |
| 参考视频 `reference_video` | ≤5 段，**总时长 ≤15s**，单文件 ≤100MB |
| 参考音频 `reference_audio` | ≤5 段，总时长 ≤15s，单文件 ≤15MB |
| 文档 `file` | ≤1 个（docx/doc/xlsx/xls/pptx/ppt/pdf/txt/md） |
| 网页 `link` | ≤1 个（公开页面） |

> ⚠️ **互斥规则**：`reference_*` / `file` / `link` 与 `first_frame` / `last_frame` **不能在同一请求里混用**。
> → 这解释了 LibTV 为什么把模式拆成 `frames2video`（首尾帧）与 `mixed2video`（全模态参考）两档，两者互斥。

### 输出规格

| 项 | 官方默认 | 备注 |
|---|---|---|
| 分辨率 | 480P / 720P / **1080P（默认）** | **LibTV 侧默认是 720P**，见 §2 |
| 宽高比 | 16:9 / 4:3 / 1:1 / 3:4 / 9:16 / **adaptive（默认）** | 全模态参考时官方建议就用 adaptive |
| 时长 | 2~30 秒；`-1` = 智能时长（**默认 5 秒**） | 有视频输入时，输入+输出总时长 ≤30s |
| 格式 | MP4，30fps | 结果 URL 有效期 **24 小时**，要及时下载 |
| 音频 | **默认开启**，`audio=false` 关闭 | 见 §5 |

## 2. 参数名对照（官方 API ↔ LibTV CLI）★

**这张表是本次"怕两边参数名对不上"的直接答案。** LibTV 用 `-s 键=值` 写生成参数，键名走模型 schema 校验。

| 概念 | 阿里云官方 API | LibTV `-s` 键（实测 schema） | 知识包旧写法 | 差异要点 |
|---|---|---|---|---|
| 模型 | `model: 'wan3.0-video'` | `model=Wan 3.0` | `model=StarVideo 2.0` | **CLI 只认 modelName，传 modelKey 会报错** |
| 提示词 | `input.prompt` | `--prompt "…"`（=`-s prompt=…`） | 同左 | 一致 |
| 任务模式 | `input.media[].type` 自动路由 | `modeType=` | `modeType=image2video` | **概念不同**：官方按素材类型路由，LibTV 固化成 modeType 档位 |
| 参考图 | `type=reference_image` | `modeType=mixed2video` + 多个 `--left` | `modeType=image2video` | wan3.0 **没有** image2video |
| 首帧 | `type=first_frame` | `modeType=singleImage2video` | — | |
| 首尾帧 | `first_frame`+`last_frame` | `modeType=frames2video` | — | |
| 视频延长 | `reference_video` + 意图词 | `modeType=videoExtend2video` | — | 仅 **wanx3.0** 与 **star-video2.5** 有此档 |
| 分辨率 | `parameters.resolution`：`480P/720P/1080P`，**默认 1080P** | `resolution=480P/720P/1080P`，**默认 720P** | `resolution=720p`（小写） | ★**默认值相反**；LibTV 侧大小写按 schema（wan 系是 `720P`） |
| 比例 | `parameters.ratio`：`adaptive` 默认 | `ratio=adaptive/16:9/4:3/1:1/3:4/9:16` | `ratio=16:9` | 一致；wan 系默认 `adaptive` |
| 时长 | `parameters.duration`：2~30 或 `-1` | `duration=2~30`；智能时长用 `duration_auto` | `duration=8` | 官方 `-1` ↔ LibTV `duration_auto=0`（Auto） |
| 音频开关 | `parameters.audio`（`true/false`），**默认 true** | `enableSound=on/off`，**默认 on** | `enableSound=off` | 同义、异名 |
| 提示词润色 | `prompt_extend` | `enablePromptOptimization` | — | 官方说它对**简短宽泛**的提示词有效 |
| 一次出几条 | — | `count=1/2/4`（**默认 1，别动**） | — | 出 2/4 条按倍数烧积分 |
| 素材指代 | 中文「图1」/ 英文「Image 1」 | 【待实测】 | `{{Image 1}}` | 见 §4 |

**其他 LibTV 侧注意**：
- `magic` / `mention` 是标记位，不是值参数（schema 里为 `true`）。
- wanx3.0 **没有** `searchEnabled` / `autoCompliance`（那是 Seedance 系才有的开关）。
- `-s model=` 的正确来源：`libtv model search -t video` 返回的 **modelName** 字段。
  wan3.0 → `Wan 3.0`；wanx3.0-prime → `Wan 3.0 Prime`。

### 2.1 控制项可达性（网页按钮 ↔ CLI）

| 控制项 | 参数 | CLI 可达性 |
|---|---|---|
| **参考素材** | `imageList` / `videoList` / `audioList` | ✅ `--left-add`（顺序 = `Image 1…N`）|
| **标记 / @ 引用** | `magic` / `mention` / `magicList` | ✅ `{{Node "名"}}` 即等效 |
| **运镜** | `params.cameraControl` + `cameraPresets` | ✅ `-s`（**图片模型的 schema 里也有 `cameraControl`**）|
| **特效** | `params.template` + 白名单（config `127`） | ⚠️ 可透传，但**无 schema 校验** |
| **角色库** | `subjectList` | ❌ 账号级资产，**无任何 API** |
| **文档 / 链接** | `supportAttachment.*` | ❌ `upload` 只支持图 / 视频 / 音频 |

- ★ **运镜 = 电影机／镜头语言预设**（4 类 29 项，每项自带英文 prompt 片段），全集 `LibTV运镜预设-config186.md`。
- 素材进生成的**唯一方式 = 画布节点 + 连线**；账号级「资产」库同样无 API（详见 §4.0）。

## 3. 提示词公式（官方四套，wan3.0 全部适用）

### 3.1 基础公式 —— 主体 + 场景 + 运动
适合放开手让模型发挥。主体是主要表现对象；场景含背景与前景；运动含主体的具体运动与非主体的运动状态（静止/小幅/大幅/局部/整体动势）。

### 3.2 进阶公式 —— 主体（描述）+ 场景（描述）+ 运动（描述）+ 美学控制 + 风格化
适合要质感和故事性。修饰靠形容词或短句列举。词表见官方文档的「电影美学控制」「动态控制」「风格化表现」三节（光源/光线/时间段/景别/构图/镜头焦段/机位角度/镜头类型/色调/运镜/情绪/视觉风格/特效）。

### 3.3 图生视频公式 —— 运动 + 运镜
画面已由参考图定死，提示词只描述**动态过程与运镜**。要锁死镜头就写「固定镜头」。

### 3.4 声音公式（`wan3.0/2.7/2.6/2.5`）—— 主体 + 场景 + 运动 + 声音描述

| 声音要素 | 公式 | 官方示例 |
|---|---|---|
| 人声 | 内容 + 情绪 + 语调 + 语速 + 音色 + 口音 | "他说道：'好好学习，天天向上'，语气轻松，语速适中，声音清亮，美式英文" |
| 音效 | 音源材质 + 行为 + 环境音 | "一个玻璃小球从桌面掉在木质地面上，发出'砰'的声音，室内安静环境" |
| 背景音乐 | 配乐 + 风格 | "配有悬疑风格背景音乐" |

### 3.5 多镜头公式（`wan3.0/2.7/2.6`）—— 总体描述 + 镜头序号 + 时间戳 + 分镜内容

官方示例（直接抄结构）：
```
这个故事以第三人称视角，讲述了一个关于放弃与重拾希望的短剧。
第1个镜头[0-3秒]一个男孩在操场的角落独自坐着，低头望着手中的信纸，随后轻轻叹气，眼神中透露出迷茫。
第2个镜头[4-6秒]硬切转场，固定机位，聚焦于男孩的眼睛，泪光闪烁，带着失落和无助。
第3个镜头[7-10秒]硬切转场，场景转至一间简朴的教室。…
```
- 要**一镜到底**：中文写「生成单镜头」，英文写 `Generate single shot.`
- wan2.7 之后**不再支持 `shot_type` 参数**指定单/多镜头，只能靠提示词控制。
- ⚠️ **wan3.0 同样不支持 `multi_shot` / `multi_prompt`**（旧范式参数，传了无用）→ **多镜头只能写在同一 prompt 里**。

### 3.6 参考生视频公式（`wan3.0/2.7`）—— 参考指代 + 动作 + 场景 + 台词（可选）+ 背景音乐（可选）

官方示例：
```
视频2抱着图3在咖啡厅里弹奏一支舒缓的美式乡村民谣，视频1笑着看着视频2。
（视频1=女性参考视频，视频2=男性参考视频，图3=吉他参考图）
```

## 4. 参考素材：从哪来、怎么指 ★（2026-09-23 查证）

> ★ **总原则：图优先于字。** 模型**对参考图忠实、对文字健忘**（知识包 30 镜实战的核心信念，`prompt-recipes.md` §0 第 1 条）⇒ **约束顺序 = 先管参考图，再管 prompt**。
> - 想要某个**画面形态**（尤其超现实变形 / 特殊构图）→ ★ **先把那个画面做出来再挂进去**（本地画 / 图片模型生成目标画面），**不要只靠文字描述它怎么变**。
> - **穿帮反复改 prompt 无效时，第一嫌疑是参考图** —— 先逐张查参考图里有没有那个元素。
> - 画面内**已有**的文字（参考图自带，如路牌）→ 模型能忠实照抄（落雁桥第 4 镜实测准确）；**要新增**的文字（片头 / 字幕卡 / 数据卡）→ 模型必然出错 → **本地 ffmpeg / Pillow 叠加**。
> - **成本含义**：变形类镜头先花 ~0.25 积分出一张目标画面图，比反复重跑视频（104 积分/次）便宜得多。
> - 出处：知识包核心信念 + `WorkBuddy\env\LibTV积分瘦身与本地化方案.html` §杠杆②。**与九宫格范式无关** —— 范式作废了，该判断在 wan3.0 上同样成立。

### 4.0 素材通路：CLI 侧没有「素材库」，唯一入口是「画布节点 + 连线」

**这条是本次查证的主结论。** 证据链有三个独立来源：

1. **命令层**：`libtv --help` 顶层只有 login / logout / account / **workspace** / project / upload / download / image / script / node / group / model。
   探测 `asset` / `library` / `material` / `media` / `resource` / `files` / `storage` 等词**全部落回顶层帮助** → **不存在素材库类子命令**。
   （`workspace` 是 1.1.3 新增的「项目 = 工作区」容器命令，**不是素材库**，别混淆。）
2. **API 层**：CLI 二进制内仅有 `/api/third_asset/create` 与 `/api/third_asset/check` 两个相关端点，
   而它们的用途是 **Seedance 系的「自动合规校验」**：把图片 URL 提交建"第三方素材"→ 轮询审核 → 通过后平台回一个 `assetId`。
   触发条件是 `shouldRunAutoCompliance` 且 `props.portrait === true` —— **wan3.0 的 schema 无 `portrait` 字段，不进这条流程**。
3. **协议层**：`applyAssetProtocolToList` 会把带 `assetId` 的素材改写成 `asset://<assetId>` 协议 URL，
   但**前置条件是 `modelSchema.properties.portrait === true`**（`needsAssetProtocol`）→ **wan3.0 不启用素材协议**。

**参数装配链路（读 CLI 二进制得到）**：

```
上游连线节点（--left）→ imageList / videoList / audioList
   → buildMixedList(...)        ← 仅 modeType=mixed2video 且未显式给 mixedList 时自动构建
   → applyAssetProtocolToList   ← wan3.0 不生效
   → 生成任务 params
```

推论（三条，都影响工作流）：

- **`mixedListOrder` 参数存在** —— 它决定素材顺序，也就是**「图1 / 图2」到底对应哪张图**。CLI 能否用 `-s` 写入待实测。
- **`mixed2video` 的素材范围 = 图片 + 视频总数 `1~15`**（其中图 ≤10、视频 ≤5，即 schema 的 `[1,15]` 与 videomax/imagemax 一致）
  → **纯图挂载成立**：只挂 1~10 张图、不带视频，模式即启用。**这是代码级证据，清单 #2 可结案。**
- `isMixed` 为真时 `audioList` 被清空，音频走独立字段 —— 说明**全模态参考下音频与图/视频是两套通道**。

**对工作流的含义**：素材**不必每个镜头重传**。素材节点在画布上建一次，多个生成节点各自连线引用它 ——
一部片子的「角色图 / 场景图 / 道具图」就落在画布上，**等价于一个项目内素材库**。
这恰好是原知识包「槽位契约」想做、但绑死在 `image2video` 上没做成的事。

### 4.1 指代语法：CLI 有自己的占位符 —— `{{Node …}}` ★（2026-09-23 结案）

**结论：CLI 侧不要用「图1」/「Image 1」，用 `{{Node …}}`。** 这是 LibTV CLI 官方命令手册明确定义的占位符层
（来源：官方 skill 包 `commands/node.md`）。

| 写法 | 语法 | 说明 |
|---|---|---|
| **按展示名（推荐）** | `{{Node "角色设定图"}}` | **成对引号**包裹上游节点**展示名**。按整张画布精确匹配；**画布内有多个同名 → 整条写入中止并报错** |
| **按 nodeKey（最稳）** | `{{Node 81e9d913-…}}` | 直接锚定节点身份，同名场景用它。**不带引号**（无引号会被当成 nodeKey） |

关键规则（官方原文）：

- 只能引用**已连线到该节点**（`--left`）的上游图片 / 视频 / 音频；未连线 → 整条写入**中止并报错**。
- `--prompt`、`-s prompt=…`、`node create` **均适用**。
- CLI **读取节点时一律把占位符显示为 `{{Node <nodeKey>}}`** —— 回读画布看到的是 key 形态，不是名字形态。
- `{{Node …}}` 是 **CLI ↔ 模型之间**的占位符层，CLI 按当前入边自动落库，**不影响网页端展示**。

**为什么这比「图1」强**：写错**会报错**（同名、未连线、找不到都中止），而不是静默失败 ——
这直接消掉了原先"提交成功 ≠ 语法正确，只能靠出片结果判断"的盲区。

**背景：与官方「图1」的关系（未废除，但 CLI 侧不必用）**

阿里云官方文档仍写「图1」/「Image 1」（图片、视频、音频分别独立计数；序号与上传顺序一致）。
`imageList` 顺序 = 连线顺序（先 `--left-add` 排第 1），所以官方序号与连线顺序对得上 ——
但**在 CLI 里没有理由退化到这一步**，直接用 `{{Node …}}`。

> `mention: true` 仍是 tool_spec 标记位（CLI 无实现），对应网页端 prompt 框的 @ 快捷补全；
> `{{Image 1}}` 是知识包（Seedance 系）的旧写法，**随槽位契约一起作废**。

## 5. 声音控制：它默认会自己做主 ★

**wan3.0 有声视频默认开启。** 更要紧的是这两条官方原文：

> - 提示词中**未描述台词** → 模型会**自由发挥添加台词**。
> - 提示词**不描述背景音乐** → 模型会**根据题材自行发挥**。

**这意味着"不写"不等于"没有"，而是等于"让模型随便加"。** 要做无声画面，两件事得**同时**做：
1. `-s enableSound=off`（关掉音频生成）
2. 提示词里显式写「**无台词**」「**无背景音乐**」（英文 `No dialogue.` / `No background music.`）

反过来，如果某镜**要**台词，就必须把台词原文写进提示词——官方说写到台词内容时，模型会**保持台词内容不变**。

## 6. 两条会改变流程范式的能力

### 6.1 多镜头：一次生成 = 一个段落，而不是一个镜头

30 秒上限 + 多镜头公式 ⇒ **可以一次生成一整个段落（含多个镜头、硬切转场）**。
这与知识包的「一镜一节点」范式**根本不同**——知识包要 30 个节点，wan3.0 可能只要 5~8 个节点。

### 6.2 视频延长：镜头连贯的正解

官方支持**向后 / 向前 / 双向**延长，画面风格与角色保持连贯：
- 向后延长 = 以最后一帧为起点继续生成
- 用法：`reference_video` + 提示词含「延长/延续/向后延长」
- `duration` 设 `-1`（自动）或「输入时长 + 预期延长时长」
- **硬限制：输入 + 输出总时长 ≤ 30 秒**

> 这是目前唯一"从机制上"解决「镜头之间融不起来」的手段——它接的是**上一镜的真实尾帧**，
> 比知识包那句「段尾留光/门/手的转场钩子」（靠剪辑缝合）强一个量级。
> LibTV 侧对应 `modeType=videoExtend2video`（wanx3.0 有；wanx3.0-prime 的 schema 没有这个档，但**带 `supportVideoContinuation` 标记**，能否用延长待实测）。

## 9. CLI 操作要点

> 本节是**当前（1.1.3）的正确做法**。命令与选项以 `libtv <cmd> --help` 为准；
> 官方命令手册全集见同目录 `libtv-cli-skill/`（`commands/` + `examples/` + `model-schema/` + `node-types/`）。

### 9.1 命令与选项

| 项 | 说明 | 用不用 |
|---|---|---|
| `workspace`（`create` / `list` / `update` / `use` / `unuse`） | 「项目（工作区）」命令组 | 单画布项目用不上；团队 / 多画布时才需要 |
| **`{{Node …}}` 占位符** | prompt 里引用已连线上游素材，见 §4.1 | ★ **指代一律用它** |
| `-u, --update <k=v>` | 改**节点自身属性**（写 `data` 顶层，**不含** `params`）—— 文本节点的 `content`、脚本/分镜的 `rows` 等 | 批量改节点内容时用 |
| `--name <text>` | 改节点**展示名**（仅默认子命令；`node create` 不接受） | 命名规范化时用 |
| `--x/--y` | 节点坐标（像素）。**写在 `create` 之前**：`libtv node --x 720 --y 260 create …`；有分组时为组内相对坐标 | 想让画布布局可读时用 |
| `download --without-ai-watermark` / `--vip` | 去水印偏好 / 声明会员（等价 `LIBTV_DOWNLOAD_IS_VIP=1`） | 交付成片下载时用 |
| `-s` 支持中文键 | 官方示例 `-s 比例=16:9` | 与英文键等价，沿用英文即可 |
| `account list` / `account use` | 多账户查看与切换 | 只在团队 / 多账号时用 |

### 9.2 术语与绑定关系（容易搞错）

- **「项目（workspace）= 工作区」是容器，「画布（project）」才是画布**；一个工作区下可放多张画布。
  官方 CLI 里 `project` 指画布，别按直觉理解成"项目"。
- `.libtv/project.json` 字段（可并存）：`projectUuid`（画布）· `workspaceId`（所属工作区）· `teamId` · `groupNodeKey`（默认分组）。
- `project use <画布UUID>` 会**同步写入**该画布所属的 `workspaceId` / `teamId`；`workspace use <项目ID>` **不设默认画布**，且会清掉原 `projectUuid` / `groupNodeKey`。
- 绑定工作区后，`project create` / `project list` **自动作用在该工作区下**；`-w <项目ID>` 覆盖，`-w 0` 回到根目录。

### 9.3 行为语义（agent 必须知道）

- **`--run` 是同步等待命令**：CLI 内部提交 → 轮询 → 写回画布，stdout 输出**终态 JSON 后退出**。
  ⇒ **外部脚本不要自己再包一层轮询，不要加 timeout，看到 `[run] task=…` 也不要提前收工**，直接等进程退出读 stdout。
- `-s model=` **只接受 modelName**（用 `libtv model search` 查名字），传 modelKey 报错。
- `--left` 是**确保模式**（无则建边、有则不变），`--left-add` 才是增量追加；`--left` 与 `--left-add/-rm` **互斥**。
- `--prompt` 与 `-s prompt=…` 同用时 **`--prompt` 后写覆盖**。
- 节点存在性：默认子命令**只操作已有节点**（不存在则报错），新建必须走 `node create -t …`。
- **`-s` vs `-u`**：`-s` 写 `data.params`（**生成器参数，走 model schema 校验**）；`-u` 写 `data` 顶层（**节点内容，不校验**）。
- **`-u` 拒写** `params` / `label` / `type` / `action` / `taskInfo` 等 ⇒ **改名只能用 `--name`**。
- **参数写在哪一层**：`params.settings` **只认** `duration` / `enableSound` / `ratio` / `resolution`（`-s ratio=16:9` 会**自动归位**到这里）；`extendPrompt` 走 `advancedSettings`；`cameraControl` 写 **`params` 顶层**。

### 9.4 注意点

- **`download` 用 `-n` / `-p` / `-g` / `-o`**（跨画布搬素材即 `download -n "<节点名>" -p <旧画布UUID> -o <目录>` → `upload "<新名>" --resource <本地路径>`）。
  官方包 `commands/` 里**没有** `download.md` —— 这条只能以 `libtv download --help` 为准（已实测）。
- CLI **没有自更新**：`--version` 只报自己。**查最新版走活动接口**（见下方"版本发现"）。

### 9.5 版本发现（★ 旧的 `latest/manifest.json` 已失效）

**唯一权威**：

```
https://api2.liblib.art/api/www/landing-activities/getById?id=240
```

响应 `data.linkUrl` 是 JSON 字符串 → `{ version, install:{CMD,PowerShell,shell}, skill }`。

## 10. 提示词铁律库（实战约束层）★

> **为什么有这一节**：§1–§2 教你「能设什么」，§3 给你「结构长什么样」，但 **「什么情况该叠什么约束」官方文档不写** —— 这节是实战经验的落点。
> 来源：`第三方知识包-保留\prompt-recipes.md`（19 条铁律）+ `production-workflow.md`（单镜 SOP），**已按 wan3.0 全模态参考范式逐条重新适配**（原版写于 Seedance + 九宫格时代，九宫格专属项已剔除）。
> 用法：**只挑当前这镜最容易出的那个坑，叠 2–4 条**。全堆上会稀释关键约束。

### 10.0 前置：扩写链路不能断 ★

官方设计是**两道扩写**，断一道画面就掉档：

| 环节 | 谁承担 | 怎么用 |
|---|---|---|
| ① 结构化整理 | 官方 `wan3-pe` skill（**只整理不扩写**，官方原文「只梳理用户已经写出的…**不替用户扩写剧情，不加入用户没提过的内容**」） | 即 §3 五段式所用 |
| ② 提示词扩写 | **平台侧**，由 `advancedSettings.extendPrompt` 承担（官方原文「关闭后生成效果大概率会下降」，默认 = 1） | ★ **保持开启，别关** |

⚠️ **`wan3-pe` 是提示词优化 Skill，不是模型** —— 与模型变体 `Wan 3.0 Prime` 毫无关系（官方原文：「平台提供万相3.0 提示词优化 Skill，方便您对提示词进行调优」，用法 `/wan3-pe + 提示词`）。

⚠️ **v1 踩的坑**：把 `extendPrompt` 关成 0，又指望 skill 帮扩写 ⇒ **两道扩写同时失效** —— "细节进不去、画面出不来"，这是效果不达预期最直接的一环。

### 10.1 通用铁律（wan3.0 适配版）

**一、正面穷举 —— 排除元素的唯一正确姿势** ★★★

- 原理：模型对「禁止/不要 X」响应差，**prompt 里出现 X 的名字反而召唤它**（"别想大象"效应）。
- 做法：**通篇不提那个名字**，改成白名单穷举。
- 模板：
  ```
  【画面元素铁律】这一镜画面里有且只有：<元素A>、<元素B>、<背景C>。
  除上述之外不出现任何其他人物、动物、道具或建筑，构图干净、主体明确。
  ```
- ⚠️ **与负面词的分工**：负面词**不要点名**你想排除的具体物体（写"出现第二座桥"= 召唤第二座桥）。负面词只放**质感/畸变类**通用项（见下面第五条）。

**二、场景锁定 —— 长镜头必带** ★★★

- 何时用：同一场景 + 单镜 >8s，或镜头大幅运动（旋转 / 穿越 / 变形）。
- 模板：
  ```
  【场景锁定铁律】全程为同一个<场景>，<建筑/陈设>的形制、相对位置、材质与颜色严格按参考图保持不变；
  禁止中途切换场景、禁止<构件>凭空消失或新增、禁止整体结构错位。
  ```
- **配套参数**：长镜头**缩到 12s 以内**（最好 8–10s）—— 时长越长，后半段越容易"重新发挥"。

**三、数量铁律 —— 防多、防分身**

```
【数量铁律】画面中<实体>数量严格等于 <N>；不允许出现第 <N+1> 个、不允许分身、不允许背景里多出同类。
```

**四、结构畸变防御 —— 变形类镜头的护身符**（wan3.0 实操新增，源自 v1 教训）

超现实变形（折叠 / 翻转 / 伸缩）是最容易出条纹噪点与几何崩坏的题材。三件事同时做：

1. 正面描述**变形的方式与秩序**（如"沿中轴对折、折痕笔直、两侧对称"），而不是只给比喻；
2. 负面词压 `横向条纹伪影、结构错位、几何畸变、噪点`；
3. **用 `cameraControl` 锁镜头语言** —— 长焦压缩畸变小，超广角放大畸变 ⇒ **变形镜头避免 8mm / 14mm**。

**五、质感词两套（全片只选一套并贯穿）**

```
A. 写实电影感：照片级真实感，真实光影与材质，浅景深，电影级打光，cinematic photoreal；
   硬负面：绝不要动画、卡通、2D插画、绘本平涂
B. 2D 柔和绘本：2D柔和动画绘本插画风格，柔和干净的线条，温暖平涂上色，温暖自然光；
   硬负面：绝不要3D渲染、C4D/Octane、写实立体、照片真实感
```

**六、文字处理 —— 与知识包相反的一条** ⚠️

- 知识包（九宫格范式）要求「画面绝对零文字」；**我们挂实景照片，参考图里本就有的文字要保留**（如落雁桥路牌）。
- 写法：
  ```
  【文字约束】画面中只出现参考图里本就存在的文字（<指明是哪个>），不新增任何其他文字、数字、字幕或水印。
  ```

**七、真人合规墙（硬边界，prompt 绕不过）**

含真人形象的参考图会被硬拦（**CG 化、裁剪都拦**）⇒ 只能网页端本人扫码做形象授权，或改纯文字描述长相（相似度打折）。

**八、防「破败滤镜」**

场景词含「农村 / 老房子 / 90 年代 / 砖房」会触发模型的贫穷破败联想 ⇒ 删掉触发词，正面描述"被打理好的温馨家"，再叠硬负面。

**九、镜头主体铁律**

```
【镜头铁律】镜头始终以 <主体> 为画面中心、紧跟不离开；禁止长段空镜、禁止环境展示式运镜；
场景只是背景，不要为了展示场景而让主体离开画面。
```

（原版写"跟人"；无人物的片改成"跟主体"。）

**十、道具在场锚定**

独立道具图 → 模型理解成"这是个素材，我来重新摆"；**「道具已摆在场景里」的合成图 → 模型理解成"照抄这个既成画面"**。照抄比重摆可靠。

**十一、人物类镜头专用**（有角色时）

- 【角色铁律】按角色定版图还原：同一张脸、同一发型、同一服装、同一年龄段，镜头之间不漂移；文字只补表情与动作，不改长相。
- 【人物比例铁律】写死年龄 + 头身比 + 禁幼态 / 大头娃娃 / 裁头 / 五官变形；发型选"成年感"款。
- 【服装渗透解法】"定版图只取脸型与发型，**衣服完全不按图**" + 正面详描新款 + 负面排原款特征（无拉链 / 无条纹）。

### 10.2 按任务类型叠哪几条（速查）

| 任务类型 | 必带 | 视情况叠加 |
|---|---|---|
| 纯场景 / 建筑镜头（本项目主线） | 场景锁定 + 正面穷举 + 质感词 | 结构畸变防御、数量、文字约束 |
| 超现实变形镜头 | 结构畸变防御 + 场景锁定 + 正面穷举 | cameraControl 选长焦、时长 ≤12s |
| 含人物镜头 | 角色 + 比例 + 镜头主体 | 服装渗透、配角虚焦、数量 |
| 长镜头（>8s） | 场景锁定 | 缩到 12s 以内 |
| 道具入镜 | 在场锚定 + 质感词 | 数量 |

### 11. 单镜生成 SOP 与分镜自查

**SOP（每镜照此走）**

1. 读素材 → 建映射（每份素材承担什么职责、采用到什么范围）
2. 写提示词：五段式（`wan3-pe` 结构）+ 按 §10.2 叠铁律 + 质感词
3. **报方案给财哥**（挂哪些图、prompt 要点、时长、全套参数）→ 得「可以 / OK」
4. `validate_generation_plan` 预检（零成本）→ 核对 `imageList` 顺序与 `cameraControl`、`extendPrompt` 是否落库
5. `--run` 生成
6. **抽帧自查**（下）→ 过了才给财哥看
7. 财哥反馈 → 逐镜返工（先定是提示词问题还是参考图问题）

**抽帧自查（每片必做，先自查再上报）**

```bash
ffmpeg -i 片.mp4 -vf "select='not(mod(n\,30))',scale=320:-1,tile=5x2" -frames:v 1 片_qc.png
```

逐条过：

- [ ] **场景一致**：形制与参考图一致，中途没漂移、没换场景
- [ ] **结构完好**：无错位、无横向条纹噪点、无几何畸变
- [ ] **数量正确**：没多出实体（桥 / 人 / 物）、没分身
- [ ] **文字正确**：只出现参考图里本就有的；无乱码、无多余字幕水印
- [ ] **运镜合规**：以主体为中心，没变成空镜 / 环境展示片
- [ ] **变形秩序**：变形方式与描述相符（是"设计好的折"而不是"崩坏"）
- [ ] **质感统一**：全程同一套质感词，没有中途换画风

**穿帮排查顺序**：反复出现且改 prompt 无效时，**先逐张检查参考图里有没有那个元素，再怀疑 prompt** —— 真凶常在参考图。

## 13. 云端剪辑边界与本地后处理

### 13.1 云端能做 / 不能做（`video-clip` 节点）

| 方式 | 能力 |
|---|---|
| **只连线** | 简单首尾拼接 |
| 写 `-u clipTimelineData` | **精细剪辑**：`clips[]` 带入点 `sourceOffset`、时长、**单 clip 音量 `decibel`**；轨级 `videoAudioVolume` / `audioTrackVolume` |

来源 id 由 CLI 按连线**自动维护**。

- ✅ **云端能做**：裁剪 / 分割 / 出入点 / 音量
- ❌ **云端不能**：转场 / 变速 / 字幕 / 超分 → 走**本地 ffmpeg**

### 13.2 本地超分（不花积分）

**A. ncnn-Vulkan（质量优先）**

- 位置 `libtv\.tmp\ncnn\`（`realesrgan-ncnn-vulkan.exe` + `models/`），A770 实测正常
- 流程：拆帧 → `realesrgan-x4plus` → cover 裁切 → 合帧（CRF 16 / slow）

**B. ffmpeg 传统法（快）** —— 本机 8.1.1

- 写实 CG 上 `scale=…:flags=lanczos,unsharp=5:5:0.7:5:5:0.0` **比 `libplacebo ewa_lanczos` 更锐且无 halo**

★ **放大倍率越大，锐化越该收敛**（2.25× 下 0.70 会出 halo，降到 0.35）。

### 13.3 成片规格

- 成片强制 **9:16**；源片非 9:16 → **「放大到覆盖 → 居中裁切」，不拉伸**。
- 输出像素：`720P` + `9:16` → **720×1280**。
- ⚠️ **`--vip` 下载的价值在码率（≈5.7×）**，别指望它去水印（实测未生效，见 `LibTV平台能力索引.md` §6.3）。
