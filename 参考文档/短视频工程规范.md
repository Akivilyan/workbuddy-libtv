## 一、需求分析（开新片第一步）✅

**必问三件（缺了就停下来问）**：

1. **片子的目标** —— 想达成什么？（讲清概念 / 展示东西 / 调动情绪 / 引流）
2. **时长** —— 多长？（未指定时按类型给默认值，见表）
3. **手上有什么素材** —— 图片 / 视频 / 音频 / 现成脚本？

**可选**（相关才问）：目标受众 · 品牌色 · 风格偏好（专业 / 创意 / 简洁 / 强烈）

**Smart defaults（没指定就用）**：受众→泛大众；风格→专业简洁；配色→中性色（黑/白/灰）+ **1 个强调色**；
时长→解释型 60–120s · 演示型 45–75s · 社交型 15–30s · 演示文稿 120–240s。

★ **纪律**：**关键问题一次问完（≤3 个），别挤牙膏**；能从上下文合理判断的直接做。

## 二、视频类型与结构骨架 ✅

**先定类型，再套骨架**。类型由「**主导目标**」决定 —— 跨类型时按主导目标**选一个**，别混。

| 类型 | 时长 | 结构骨架 | 对 AI 生成画面 |
|---|---|---|---|
| **社交短片**（竖屏主力） | 15–60s | Hook → Message → Visual → CTA | ★ 最贴合 |
| **解释型** | 60–180s | Hook → Problem → Solution → How → Benefits → CTA | ★ 贴合 |
| **发布公告** | 10–15s | Hook → 卖点 → Before/After → CTA | ★ 贴合 |
| **新旧对比** | 10–20s | 背景 → Before → 转场 → After → 量化结论 | ★ 贴合 |
| 演示文稿 | 120–300s | 标题 → 内容页 → 总结 → 收尾 | ⚠️ 部分 |
| Top N / 文字动效 / UI 走查 / 帖文总结 / 版本公告 / 音乐可视化 | 15–60s | 见插件原件 | ❌ 属排版动效类，非 AI 画面 |

**常用骨架速查**：

| 场景 | 骨架 |
|---|---|
| **30 秒竖屏通用** | Hook 3s → Message 12s → Visual 10s → CTA 5s |
| Top N 榜单 | 标题卡 2s → 条形排名（**每条 1.5–2s**）→ 洞察 2s；条目交错 45–60 帧；**必标数据来源** |
| 新旧对比 | 背景 2s → Before 5s → 转场 2s → After 5s → **量化结论 3s（必须给倍数）** |
| 发布公告 | Hook ≤8 词 → 3 个卖点（各 1.5s）→ Before/After → CTA；**全片只用 1 个强调色** |
| 信息流 / 总结 | 每点 3–6 秒 + 进度点指示 |

## 三、节奏规则 ✅

- 每行文字停留 **≥2 秒**（阅读速度 200–250 WPM）
- **场景类型标准时长**：Hook 3–5s / Content 10–15s / Feature 10–12s / Transition 1–2s / CTA 5–7s
- 单场景 3–20 秒；场景之间留 30–60 帧"呼吸"
- 转场 **<1 秒**（20–30 帧）
- **入场 15–20 帧，退场比入场快 30%**；列表项 stagger 15–30 帧
- **每 8–10 秒必须有一个视觉变化点**（防视觉疲劳）
- 片头 Hook **2–3 秒内必须出现核心信息**；片尾 CTA 至少保持 3 秒
- 不要所有场景等长 —— 重要内容给更多时间
- 快-慢-快节奏：hook 快 → 内容稳 → CTA 快

### 场景类型与标准时长

| 场景类型 | 作用 | 时长 |
|---|---|---|
| Title / Hook | 抓注意力、引入主题 | **3–5s** |
| Content | 交付主要信息 | **10–15s** |
| Feature | 突出某个功能（演示类） | **10–12s** |
| Transition | 段落之间的桥 | **1–2s** |
| CTA | 驱动行动 | **5–7s** |

### 帧计算

```
duration_frames = duration_seconds × fps
```

累积起点：场景 1 从 0 开始；场景 N 的起点 = 前序所有场景帧数之和。例：5s @30fps = 150 帧。

### 交错（stagger）时序

- 列表项之间：**15–30 帧**
- 词与词之间：**5–10 帧**
- 字符之间（打字机）：**2–3 帧**

（动画时长：Fade 15–30 帧 / Slide 20–40 帧 / Scale 15–30 帧。）

## 四、版面与可读性 ⚠️（仅本地叠字 / 字幕卡）

> ⚠️ **基准分辨率**：原始文档以 1920×1080 横屏为基准。我们成片是 **720×1280 竖屏**（0.375 倍宽），**数值需按比例换算后使用**，别直接照搬。

| 项 | 规格（1080 宽基准） | 720 宽换算 |
|---|---|---|
| 安全区 | 侧 60px / 上 80px / 下 120px | 侧 40 / 上 53 / 下 80（**下沿永远留最多**，防平台 UI 遮挡） |
| 字号阶梯 | 72 / 60 / 48 / 36 / 28 / 24 / 18 | 同比例缩放；**重要文字不低于 24px** |
| 字号层级 | Hero 72px+ / H1 48–60 / H2 36–48 / Body 24–32 / Caption 16–20 | — |
| 行宽上限 | 中文 ≤30 字 / 英文 ≤60 字符 | 不变（与字号相关，与画幅无关） |
| 版式分区 | 标题 20% / 主体 70% / 留白 10% | 不变（比例） |
| 栅格 | 8px 对齐 | 换算后取整 |
| 对比度 | **普通文字 ≥4.5:1**；大文字与图形 ≥3:1 | 不变 |
| 文字压图 | **必须加描边或半透明底板** | 不变 |
| 圆角 / 阴影 | 圆角统一（8/12/16 选一套）；深色底阴影 `0 8px 24px rgba(0,0,0,.4)` | 不变 |

**色彩纪律**：
- 颜色不超过 4 种（主色 / 强调色 / 背景 / 文字）；**同一场景不超过 3 种**；全片只用 1 个强调色
- 背景**不要纯黑** `#000000`（用 `#0A0A0A` / `#0F172A`）；文字**不要纯白** `#FFFFFF`（用 `#F8FAFC`）
- 强调色饱和度**降 10–20%**
- 字体 weight：**标题 700–800，正文 400–500**（别用 400 做标题）；数字用等宽（tabular-nums）防跳动
- 中文字体参考：Noto Sans SC / 思源黑体

**色彩心理学（选主色时用）**：

| 色 | 传递 |
|---|---|
| 蓝 | 信任、专业、科技 |
| 绿 | 成长、健康、环保 |
| 紫 | 创意、高级、创新 |
| 橙 / 红 | 能量、紧迫、兴奋 |
| 黑 / 白 | 优雅、简洁、清晰 |

**字重阶梯**：400 正文 · 500 中等 · 600 半粗 · 700 粗（标题）· 800–900 特粗（主视觉）

**内边距参考**：标题与正文之间 40–60px · 段落之间 30–40px · 列表项之间 20–30px

**栅格**：12 列对齐；间距取 **8 的倍数**（8 / 16 / 24 / 32 / 40 / 48）

## 五、音频纪律 ✅

- BGM 音量 **≤0.3**（不要盖过画面）；片尾 2 秒渐出
- 音效**克制**：只在场景切换（whoosh）、关键数字出现（pop）等少数位置
- **不要每个动效都配音效**
- 音频时长必须 ≥ 视频时长

## 六、动效纪律与反模式 ✅

**动效风格三档**（前置选定，**全片统一**）：

| 风格 | 适用 |
|---|---|
| `smooth` 柔和 | 标题、大面积元素 |
| `snappy` 灵敏 | 按钮、小元素 |
| `bouncy` 弹跳 | 强调、惊喜时刻 |

**反模式清单（避免）**：

- ❌ 逐字符透明度做打字机（布局会跳动）
- ❌ 无固定宽度的文字容器（词轮播会抖）
- ❌ 转场 >45 帧（节奏拖沓）；✅ 控制在 15–25 帧
- ❌ 突然硬切、❌ 旋转 / 弹跳式转场
- ❌ 背景动效抢字
- ❌ 所有动画都用线性（机械感强）
- **每个动效都要有理由，没理由的去掉**

## 七、分镜表标准格式 ✅（出片前必填）

```markdown
# 分镜表：<标题>

## 全局设定
- 画幅 / fps / 总时长（秒 + 帧）
- 配色：主色 / 强调色 / 背景
- 字体：主 / 备
- 动效风格：smooth | snappy | bouncy

## Scene 列表
| # | 名称 | 时长 | 帧范围 | 内容 | 转场 | 动效 | 素材 |
|---|------|------|--------|------|------|------|------|
| 1 | Hook | 4s | 0-120 | … | fade-in | … | 无 |

## 素材清单
- [ ] …
```

**此格式与 LibTV 流程的接口**：填完分镜表 → 每行对应一个（或一组）LibTV 节点 → 走 `出片规范` 的单镜 SOP。

## 八、审片清单 ✅（与出片规范 §11 互补）

出片规范 §11 的自查管**镜头内部**（结构 / 畸变 / 数量 / 文字）；本清单管**片子层面**：

- [ ] **节奏**：每行文字停留 ≥2s；hook 2–3s 内出核心信息；CTA ≥3s
- [ ] **变化点**：每 8–10 秒有一个视觉变化点
- [ ] **统一**：字体 / 颜色 / 动效风格全片一致（没中途换画风）
- [ ] **可读性**：文字在安全区内；对比度达标；压图文字有底板
- [ ] **颜色数量**：每场景 ≤3 色，全片强调色只有 1 个
- [ ] **声音**：BGM 不盖画面；片尾渐出；音效克制
- [ ] **反模式**：无硬切、无旋转/弹跳转场、无逐字符透明度

## 九、迭代策略 ✅（由内到外，五轮）

1. **结构** —— 内容正确、时间线合理
2. **视觉** —— 统一设计系统（字体 / 颜色 / 对比度）
3. **动效** —— 让画面活起来
4. **细节** —— 排版与层次
5. **性能** —— 优化渲染

**常见问题 → 对策**：看起来"很 AI"→ 统一视觉系统 + 色彩精修；转场生硬 → 平滑转场；文字看不清 → 色彩 + 层次；节奏怪异 → 调节奏；排版凌乱 → 排版精修。

**工程纪律**：① 先出分镜与节奏表，确认后再生成；② 参数常量集中在一处（便于改一版重出）；③ **迭代增量** —— 从简单开始逐步加元素，比一次性要复杂效果更稳定。

## 十、报方案模板 ✅（生成前必报）

```markdown
## 概况
- 时长：X 秒 · 场景数：N · 风格：<专业/创意/简洁>
- 画幅与分辨率：<如 720×1280 竖屏>

## 分镜流
1. **<场景名>**（0-5s）—— 一句话描述
2. **<场景名>**（5-15s）—— …

## 需要的素材
- 必需：…
- 可选：…

## 下一步
说明接下来做什么（生成 / 剪辑 / 超分），然后问：**「可以吗？还是要调整？」**
```

**四种反馈的处理**：

| 回复 | 处理 |
|---|---|
| 「可以 / OK」 | 进入生成 |
| 「改 X」 | 改完**重新报一遍**，别直接开跑 |
| 「缺某个素材」 | 必需 → 请对方提供或给替代；可选 → 跳过并说明 |
| 「长一点 / 短一点」 | 重排分镜，**重新报** |

## 十一、协作规范 ✅

**四条姿态**：

- **主动** —— 自动识别意图、给合理默认、少让人输入
- **透明** —— 每一步在做什么都说；耗时提前讲；进度如实报
- **有用** —— 给预览、给完整路径与命令、给下一步建议、留出可改的余地
- **宽容** —— 素材缺失优雅降级；出错能恢复；有问题先给替代方案

**进度符号**：`✓` 完成 · `→` 进行中 · `⚠` 警告 · `❌` 错误 · `ℹ` 说明

**给指令时**：给**精确命令**、给**完整路径**、解释这一步在干什么。
